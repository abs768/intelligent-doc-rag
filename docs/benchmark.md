### What is and isn't claimed

- **Quality** is reported ONLY for the `json` category, where pass means "output is a valid JSON object and contains every required key". Required keys are defined in `prompts.yaml`.
- The `factual` and `rag` categories are reported as **latency/throughput only**. Substring-matching small models against a reference answer is too unreliable to call "correctness", so those numbers are not in this report.
- **TTFT** is approximated as `load_duration + prompt_eval_duration` from the non-streaming response — a reasonable lower bound for time-until-first-token, but not a streaming-client measurement.
- All timings come from Ollama's own response payload (nanoseconds → ms here). Wall-clock latency is measured client-side.

## Reproducing

```bash
# Pull models locally first:
ollama pull tinyllama:latest
ollama pull llama3.2:3b
ollama pull llama3:latest

# Then from backend/:
mvn spring-boot:run \
  -Dspring-boot.run.main-class=com.chatassistant.aichatassistant.bench.BenchmarkMain \
  -Dspring-boot.run.arguments="--models=tinyllama:latest,llama3.2:3b,llama3:latest --iterations=3"
```
